# 미트박스 TMS 데모 시나리오

**대상 기능: ② 고객 배송 트래킹 · ③ 다이나믹 ETA**

> 근거 문서: 「미트박스 TMS 역할 요약」 요구사항 정리서.
> 기능 ①(권역 설정 최적화)은 본 데모 범위에서 제외한다.

---

## 1. 데모 목표

고객사 요구사항의 핵심 문장 — **"내 물건이 어디 있는지, 언제 오는지"** — 를 하나의 배송 건이 주문에서 문 앞 도착까지 흘러가는 스토리로 보여준다.

시연을 통해 증명할 것:

1. 주문~배송 완료까지 **9단계 상태가 스캔 이벤트로 자동 전환**되고, 고객 화면·관제 화면·알림에 즉시 반영된다 (기능 ②)
2. ETA가 **시간 범위("13:00~14:00 도착 예정")로 표시**되고, 운영 중 발생하는 3가지 트리거(교통 이슈 / 기사 순서 변경 / 하차 지연)에 의해 **자동 재계산·즉시 반영**된다 (기능 ③)
3. ETA 변동 폭이 기준 이상이면 고객에게 **"배송 예정 시간이 변경되었습니다"** 안내가 발송되고, 관제 화면에서 **어떤 고객에게 어떤 알림이 나갔는지** 확인된다 (기능 ② + ③)
4. **고객·기사·관리자 각각 계정이 여러 개인 상황**에서도 동작한다 — 고객은 본인 주문만, 기사는 본인 배차만 보고, 관리자는 전체를 실제 지도에서 관제하며, 여러 세션이 동시에 접속해도 같은 상태를 실시간 공유한다

## 2. 데모 형태 및 화면 구성

웹 기반 데모 앱, 목데이터 + 이벤트 시뮬레이션으로 구동한다. 접속 시 **계정 선택(간이 로그인)** 을 거쳐 역할별 화면으로 진입하며, 화면은 4개.

| 화면 | 사용자 | 역할 |
|---|---|---|
| **A. 고객 모바일 화면** | 고객 (계정 여러 개) | 미트박스 앱의 주문 상세: 상태 타임라인, 지도 위 기사 위치, ETA 카드, 배송 순번("N번째 배송 예정"), 푸시/알림톡 수신 재현. **본인 주문만 보인다** |
| **B. 기사 앱 화면** | 전용차 기사 (계정 여러 개) | **배송 완료 체크 전용**: 본인 배차의 당일 배송 리스트, 착지별 하차 완료 체크 + 문 앞 사진 첨부. **본인 배차만 보인다** |
| **C. 관리자 관제 화면** | 미트박스 관제 운영자 (계정 여러 개) | **실제 지도(지도 타일) 기반 관제**: 전체 차량 실시간 위치·경로·교통 이슈, 당일 배차·진행 현황, 배송 건별 상태 보드와 스캔 로그, ETA 변동 이벤트 피드, 알림 발송 현황, ETA 정확도 리포트 탭. **전체가 보인다** |
| **D. 시연 컨트롤러** | 시연자 | MFC 스캔 이벤트 발생, 기사 이동·출발·순서 변경 이벤트 주입, 교통 이슈·하차 지연 주입, 시간 빨리감기 — 시나리오를 진행시키는 리모컨 |

역할 분담: 기사 앱은 **배송 완료 체크**만 담당한다. 출발·이동·순서 변경 등 나머지 현장 이벤트는 컨트롤러(D)가 주입한다.

브라우저 창 여러 개에 각기 다른 계정으로 로그인해 나란히 띄워 두고 D로 이벤트를 쏘면, **하나의 현장 이벤트가 각 역할 화면에 권한에 맞게 동시 반영되는 순간** — 기사가 완료를 체크하면 해당 고객에게만 완료 알림이 가고, 관제 지도에서는 전체 그림이 갱신된다 — 이 데모의 하이라이트가 된다.

## 3. 등장 인물 / 계정 구성

멀티 계정 시연을 위해 역할별로 계정을 2개 이상 둔다.

| 역할 | 계정 | 설정 |
|---|---|---|
| 고객 1 | 성수동 «금돼지식당» 김 사장 | 삼겹살 등 6박스 주문, 박 기사 차량의 **7번째** 배송지 — 메인 스토리 |
| 고객 2 | 마장동 «한우명가» 이 사장 | 소갈비 등 4박스 주문, 박 기사 차량의 **2번째** 배송지 — 계정 전환 시연용 |
| 기사 1 | 성동 권역 전용차 박 기사 | 당일 착지 12곳 — 메인 스토리 차량 |
| 기사 2 | 광진 권역 전용차 최 기사 | 당일 착지 10곳 — 관제 지도의 다중 차량 시연용 |
| 관리자 1 | 관제팀 정 매니저 | 관제 화면 메인 시연 |
| 관리자 2 | 관제팀 강 팀장 | 별도 창 동시 접속 — 멀티 세션 실시간 동기화 시연용 |

- **출고지**: 미트박스 성동 MFC
- **시간대**: 새벽 배송 (04:00 상차 → 오전 중 배송 완료)

## 4. 시나리오 플로우 (Scene별)

상태값 9단계: `주문 접수 → 결제 완료 → 피킹 중 → 라벨 부착 → 상차 대기 → 배송 출발 → N번째 순서 배송 예정 → 인근 배송 중 → 배송 완료`

### Scene 0 — 계정과 화면 세팅 (멀티 계정)

브라우저 창 4개를 띄우고 각각 로그인: 고객 김 사장(A), 기사 박 기사(B), 관리자 정 매니저(C), 시연 컨트롤러(D). 필요 시점에 고객 이 사장·관리자 강 팀장 창을 추가로 연다.

**시연 멘트**: "같은 시스템에 고객·기사·관리자가 각자의 계정으로 접속합니다. 고객은 본인 주문만, 기사는 본인 배차만 보이고, 관리자는 전체를 봅니다."

### Scene 1 — 주문과 출고 준비 (기능 ②)

| 진행 | 화면/알림 |
|---|---|
| 전날 밤, 김 사장과 이 사장이 각각 주문·결제 | A(김 사장): 타임라인 `주문 접수` → `결제 완료` — 이 사장 주문은 보이지 않음 / C: 상태 보드에 두 건 모두 등록 |
| 새벽 MFC에서 피킹 스캔 → 라벨 스캔 → 상차 대기 스캔 (D에서 순차 발생) | A: `피킹 중` → `라벨 부착` → `상차 대기` 자동 전환 / C: 스캔 이벤트 로그가 실시간으로 쌓이고 상태 보드 갱신 |

**시연 멘트**: "각 상태 전환은 구간별 스캔 활동으로 자동 처리됩니다. 운영자가 상태를 손으로 바꾸는 일이 없고, 관제 화면에서는 모든 스캔 이력이 그대로 추적됩니다."

### Scene 2 — 배송 출발과 최초 ETA, 다중 차량 관제 (기능 ② + ③)

| 진행 | 화면/알림 |
|---|---|
| D에서 박 기사·최 기사 "상차 완료·배송 출발" 주입 | C: **실제 지도에 차량 2대가 각자의 경로(12곳/10곳)로 동시 출발** / B(박 기사): 본인 배차 12건 리스트 표시 — 최 기사 배차는 보이지 않음 / A: `배송 출발` 전환, **푸시 + 알림톡** "김 사장님의 상품이 배송을 시작했습니다" |
| ETA 최초 산출 | A: ETA 카드 **"06:30 ~ 07:00 도착 예정"** + **"고객님은 7번째 배송 예정입니다"** / C: 배송 건별 ETA 목록 표시 |

**시연 멘트**: "관제는 실제 지도 위에서 전체 차량을 한눈에 봅니다. ETA는 배송 이력 데이터와 실시간 교통정보를 결합해 시간 범위로 제공하며, 목표 정확도는 ±15분 이내 80% 이상입니다."

### Scene 3 — 배송 진행, 기사 완료 체크와 계정 전환 (기능 ②)

| 진행 | 화면/알림 |
|---|---|
| D에서 시간 빨리감기 — 박 기사가 1번째 착지 도착, **기사 앱(B)에서 하차 완료 체크** | B: 1건 완료 처리 / C: 지도 위 차량 이동, 진행 현황 **1/12** / A(김 사장): 순번 **7번째 → 6번째** |
| **고객 계정 전환**: 이 사장 창으로 이동 | A(이 사장): 같은 차량인데 **"2번째 배송 예정"** — 곧 도착. 본인 주문(소갈비 4박스)만 보임 |
| 박 기사가 2·3번째 완료 체크 (이 사장 배송 포함) | A(이 사장): `배송 완료` / A(김 사장): 순번 **4번째** / C: 진행 현황 **3/12**, 최 기사 차량도 각자 경로로 이동 중 |

**시연 멘트**: "고객마다 자기 주문 기준의 순번과 ETA를 봅니다. 기사의 완료 체크 한 번이 해당 고객의 완료 알림, 다른 고객의 순번 감소, 관제 진행률 갱신으로 동시에 퍼집니다."

### Scene 4 — ETA 재계산 트리거 ①: 실시간 교통 이슈 (기능 ③)

| 진행 | 화면/알림 |
|---|---|
| D에서 "성수대교 진입로 사고" 주입 (TMAP/네이버 교통정보 수신 상황 재현) | C: **실제 지도에 사고 아이콘** + 박 기사 우회 경로 재탐색, ETA 변동 이벤트 피드에 경보 — 영향받는 박 기사 잔여 9건 하이라이트. **최 기사 차량은 영향 없음** (차량별 독립 재계산) |
| ETA 자동 재계산, 변동 폭 기준(예: 20분) 초과 | A(김 사장): ETA **"06:30~07:00" → "07:00~07:30"** 갱신 + 알림 **"배송 예정 시간이 변경되었습니다"** / C: 알림 발송 현황에 "지연 안내 9건 발송" 기록 / **관리자 강 팀장 창에서도 동일 경보가 동시에 표시** (멀티 세션 동기화) |

**시연 멘트**: "변동 폭이 기준 이내면 조용히 갱신하고, 기준을 넘으면 고객에게 별도 안내합니다. 어떤 고객에게 어떤 알림이 나갔는지 관제에서 즉시 확인되고, 여러 관리자가 동시에 봐도 같은 상태를 공유합니다."

### Scene 5 — ETA 재계산 트리거 ②: 기사 순서 수동 변경 (기능 ③)

| 진행 | 화면/알림 |
|---|---|
| D에서 기사 이벤트 "박 기사 5·6번째 배송지 순서 교체" 주입 (현장 사정 재현) | B: 본인 배송 리스트 순서가 재배열됨 / C: 이벤트 로그에 순서 변경 기록, 지도 경로 재배열 / A(김 사장): 순번 **4번째 → 3번째**, ETA 범위 앞당겨짐. 변동 폭이 기준 이내라 **별도 알림 없이 화면만 갱신** |

**시연 멘트**: "기사 동선 변경이 기사·관제·고객 화면에 즉시 반영됩니다. 트리거 ③(앞 배송지 하차 지연)도 같은 메커니즘으로 동작합니다."

> 시간이 허락하면 D에서 "앞 배송지 하차 지연(15분 정차)"을 주입해 트리거 ③까지 시연한다.

### Scene 6 — 인근 배송 중 → 기사 앱 배송 완료 체크 (기능 ②)

| 진행 | 화면/알림 |
|---|---|
| 차량이 반경 기준 내 진입 | A(김 사장): `인근 배송 중` + 푸시 "기사님이 인근에서 배송 중입니다" |
| **박 기사가 기사 앱(B)에서 김 사장 건 하차 완료 체크 + 문 앞 사진 첨부** | A(김 사장): `배송 완료` + 완료 알림(사진 첨부), 타임라인 전체 완결 / B: 7/12 완료 / C: 진행 현황 갱신, 배송 건 상세에 완료 사진 확인 |

**시연 멘트**: "기사 앱의 역할은 단순합니다 — 완료 체크와 사진 한 장. 그 한 번의 입력이 고객의 완료 알림과 관제 기록으로 이어집니다."

### Scene 7 — 에필로그: 관제 화면의 정확도 리포트 (기능 ③ 보조)

관리자 화면(C)의 **ETA 정확도 리포트 탭**으로 전환: 최근 30일 **ETA ±15분 적중률 추이(예: 68% → 82%)**, 재계산 발생 사유 분포(교통/순서 변경/하차 지연).

**시연 멘트**: "배송 이력이 Data Mart에 쌓일수록 예측이 좋아집니다. 초기 60~70%에서 시작해 80% 이상을 달성하는 단계적 로드맵을 관제 화면의 지표로 관리합니다."

## 6. 데모 데이터 및 기술 처리

- **계정**: 고객 2, 기사 2, 관리자 2 (3장 표 기준). 데모용 간이 로그인(계정 선택)으로 진입하며, 역할·계정별 데이터 격리 — 고객은 본인 주문만, 기사는 본인 배차만, 관리자는 전체
- **배송 데이터**: 박 기사 12건 + 최 기사 10건 = 22건 (성동·광진 권역 실제 지명·좌표 사용), 상태 이벤트는 전부 시뮬레이터가 발생
- **지도**: 관제 화면은 **실제 지도 타일 사용** (예: Leaflet + OpenStreetMap — API 키 불필요). 차량 위치·경로·착지·교통 이슈를 실제 좌표 위에 표시하고, 고객 화면 지도도 같은 지도 데이터를 공유
- **실시간 동기화**: 이벤트를 접속 중인 모든 세션에 브로드캐스트 — 같은 역할 계정이 여러 창으로 동시에 접속해도 동일 상태를 실시간 공유
- **ETA 목업 산식**: `잔여 배송 수 × 착지당 평균 처리시간 + 구간 이동시간 × 교통 가중치`, 결과를 30분 범위로 라운딩 — AI 모델의 동작을 규칙 기반으로 흉내 낸다

## 7. 데모 범위 제외 (Out of Scope)

- TMAP/네이버지도 **실제 교통 API 연동** — 교통 이슈는 시뮬레이터 주입으로 재현 (지도 타일 자체는 실제 지도 사용)
- 카카오 알림톡 **실제 발송** — 화면 내 수신 UI로 재현
- **AI 예측 모델 실물** — 규칙 기반 목업으로 대체
- **실제 인증 체계**(소셜 로그인, 비밀번호 등) — 데모용 간이 계정 선택으로 대체
- 기능 ①(권역 설정 최적화), 실 결제, 실 주문 연동
