# 미트박스 TMS 데모 시나리오

**대상 기능: ② 고객 배송 트래킹 · ③ 다이나믹 ETA**

> 근거 문서: 「미트박스 TMS 역할 요약」 요구사항 정리서.
> 기능 ①(권역 설정 최적화)은 본 데모 범위에서 제외한다.

---

## 1. 데모 목표

고객사 요구사항의 핵심 문장 — **"내 물건이 어디 있는지, 언제 오는지"** — 를 하나의 배송 건이 주문에서 문 앞 도착까지 흘러가는 스토리로 보여준다.

시연을 통해 증명할 것:

1. 주문~배송 완료까지 **9단계 상태가 스캔 이벤트로 자동 전환**되고, 고객 화면·관제 화면·알림에 즉시 반영된다 (기능 ②)
2. ETA가 **시간 범위("13:00~14:00 도착 예정")로 표시**되고, 운영 중 발생하는 3가지 트리거(교통 이슈 / 기사 순서 변경 / 하차 지연)에 의해 **자동 재계산·즉시 반영**된다 (기능 ③)
3. ETA 변동 폭이 기준 이상이면 고객에게 **"배송 예정 시간이 변경되었습니다"** 안내가 발송되고, 관제 화면에서 **어떤 고객에게 어떤 알림이 나갔는지** 확인된다 (기능 ② + ③)

## 2. 데모 형태 및 화면 구성

웹 기반 단일 데모 앱, 목데이터 + 이벤트 시뮬레이션으로 구동한다. 화면은 3개.

| 화면 | 사용자 | 역할 |
|---|---|---|
| **A. 고객 모바일 화면** | 고객(식당 사장) | 미트박스 앱의 주문 상세: 상태 타임라인, 지도 위 기사 위치, ETA 카드, 배송 순번("N번째 배송 예정"), 푸시/알림톡 수신 재현 |
| **B. 관리자 관제 화면** | 미트박스 관제 운영자 | 지도 관제(차량 실시간 위치·경로·교통 이슈), 당일 배차·배송 진행 현황(N/12 완료), 배송 건별 상태 보드와 스캔 이벤트 로그, ETA 변동 이벤트 피드, 알림 발송 현황, ETA 정확도 리포트 탭 |
| **C. 시연 컨트롤러** | 시연자 | 스캔 이벤트 발생, 기사 앱 이벤트(출발·하차·순서 변경) 주입, 교통 이슈·하차 지연 주입, 시간 빨리감기 — 시나리오를 진행시키는 리모컨 |

기사 화면은 데모에 두지 않는다. 기사 행동(상차·하차 스캔, 배송 순서 변경)은 **컨트롤러(C)가 "기사 앱에서 발생한 이벤트"로 주입**하고, 그 결과를 관제 화면(B)과 고객 화면(A)에서 보여준다.

A·B를 나란히 띄워 두고 C로 이벤트를 쏘면, **현장 이벤트가 관제 화면과 고객 화면에 동시에 실시간 반영되는 순간** — 운영자와 고객이 같은 사실을 같은 시점에 본다 — 이 데모의 하이라이트가 된다.

## 3. 등장 인물 / 설정

- **고객**: 성수동 «금돼지식당» 김 사장 — 전날 밤 미트박스 앱에서 삼겹살 등 6박스 주문
- **관제 운영자**: 미트박스 관제팀 이 매니저 — 관리자 화면(B)에서 당일 배송을 관제
- **기사**: 성동 권역 전용차 박 기사 — 당일 착지 12곳, 김 사장은 **7번째** 배송지 (화면에는 등장하지 않고 이벤트로만 존재)
- **출고지**: 미트박스 성동 MFC
- **시간대**: 새벽 배송 (04:00 상차 → 오전 중 배송 완료)

## 4. 시나리오 플로우 (Scene별)

상태값 9단계: `주문 접수 → 결제 완료 → 피킹 중 → 라벨 부착 → 상차 대기 → 배송 출발 → N번째 순서 배송 예정 → 인근 배송 중 → 배송 완료`

### Scene 1 — 주문과 출고 준비 (기능 ②)

| 진행 | 화면/알림 |
|---|---|
| 전날 밤, 김 사장이 주문·결제 | A: 타임라인 `주문 접수` → `결제 완료` / B: 상태 보드에 신규 배송 건 등록 |
| 새벽 MFC에서 피킹 스캔 → 라벨 스캔 → 상차 대기 스캔 (C에서 순차 발생) | A: `피킹 중` → `라벨 부착` → `상차 대기` 자동 전환 / B: 스캔 이벤트 로그가 실시간으로 쌓이고 상태 보드 갱신 |

**시연 멘트**: "각 상태 전환은 구간별 스캔 활동으로 자동 처리됩니다. 운영자가 상태를 손으로 바꾸는 일이 없고, 관제 화면에서는 모든 스캔 이력이 그대로 추적됩니다."

### Scene 2 — 배송 출발과 최초 ETA (기능 ② + ③)

| 진행 | 화면/알림 |
|---|---|
| C에서 기사 앱 이벤트 "상차 완료·배송 출발" 주입 | B: 지도에 차량 출발, 12개 착지 경로 표시 / A: `배송 출발` 전환, **푸시 + 알림톡** 동시 수신 재현: "김 사장님의 상품이 배송을 시작했습니다" |
| ETA 최초 산출 | A: ETA 카드 **"06:30 ~ 07:00 도착 예정"** + **"고객님은 7번째 배송 예정입니다"** / B: 배송 건별 ETA 목록 표시 |

**시연 멘트**: "ETA는 배송 이력 데이터와 실시간 교통정보를 결합해 시간 범위로 제공합니다. 목표 정확도는 ±15분 이내 80% 이상입니다."

### Scene 3 — 배송 진행, 순번 카운트다운 (기능 ②)

| 진행 | 화면/알림 |
|---|---|
| C에서 시간 빨리감기 — 1~3번째 배송지 하차 스캔 이벤트 발생 | B: 지도 위 차량 이동, 진행 현황 **3/12 완료** / A: 순번 **7번째 → 4번째**로 감소, ETA 범위 유지 |

**시연 멘트**: "고객은 기사에게 전화하지 않아도 내 순서와 위치를 직접 관제할 수 있고, 관제팀도 문의 전화를 받기 전에 현황을 먼저 봅니다."

### Scene 4 — ETA 재계산 트리거 ①: 실시간 교통 이슈 (기능 ③)

| 진행 | 화면/알림 |
|---|---|
| C에서 "성수대교 진입로 사고" 주입 (TMAP/네이버 교통정보 수신 상황 재현) | B: 지도에 사고 아이콘 + 우회 경로 재탐색, **ETA 변동 이벤트 피드에 경보 발생** — 영향받는 배송 건(잔여 9건) 하이라이트 |
| ETA 자동 재계산, 변동 폭 기준(예: 20분) 초과 | A: ETA **"06:30~07:00" → "07:00~07:30"** 갱신 + 알림 **"배송 예정 시간이 변경되었습니다"** / B: 알림 발송 현황에 "지연 안내 9건 발송" 기록 |

**시연 멘트**: "변동 폭이 기준 이내면 조용히 갱신하고, 기준을 넘으면 고객에게 별도 안내합니다. 관제 화면에서는 어떤 고객에게 어떤 알림이 나갔는지 즉시 확인됩니다 — 스팸성 알림을 막는 정책 포인트입니다."

### Scene 5 — ETA 재계산 트리거 ②: 기사 순서 수동 변경 (기능 ③)

| 진행 | 화면/알림 |
|---|---|
| C에서 기사 앱 이벤트 "5·6번째 배송지 순서 교체" 주입 (현장 사정 재현) | B: 경로 순서 변경이 이벤트 로그에 기록되고 지도 경로 재배열 / A: 순번 **4번째 → 3번째**, ETA 범위 앞당겨짐. 변동 폭이 기준 이내라 **별도 알림 없이 화면만 갱신** |

**시연 멘트**: "기사 동선 변경이 관제와 고객 화면에 즉시 반영됩니다. 트리거 ③(앞 배송지 하차 지연)도 같은 메커니즘으로 동작합니다."

> 시간이 허락하면 C에서 "앞 배송지 하차 지연(15분 정차)"을 주입해 트리거 ③까지 시연한다.

### Scene 6 — 인근 배송 중 → 배송 완료 (기능 ②)

| 진행 | 화면/알림 |
|---|---|
| 차량이 반경 기준 내 진입 | A: `인근 배송 중` + 푸시 "기사님이 인근에서 배송 중입니다" |
| C에서 하차 스캔 + 문 앞 사진 이벤트 주입 | A: `배송 완료` + 완료 알림(사진 첨부), 타임라인 전체 완결 / B: 진행 현황 갱신, 배송 건 상세에 완료 사진 첨부 확인 |

### Scene 7 — 에필로그: 관제 화면의 정확도 리포트 (기능 ③ 보조)

관리자 화면(B)의 **ETA 정확도 리포트 탭**으로 전환: 최근 30일 **ETA ±15분 적중률 추이(예: 68% → 82%)**, 재계산 발생 사유 분포(교통/순서 변경/하차 지연).

**시연 멘트**: "배송 이력이 Data Mart에 쌓일수록 예측이 좋아집니다. 초기 60~70%에서 시작해 80% 이상을 달성하는 단계적 로드맵을 관제 화면의 지표로 관리합니다."

## 6. 데모 데이터 및 ETA 목업 로직

- 배송 12건(착지 12곳, 성동 권역 실제 지명 사용), 상태 이벤트는 전부 시뮬레이터가 발생
- ETA 목업 산식: `잔여 배송 수 × 착지당 평균 처리시간 + 구간 이동시간 × 교통 가중치`, 결과를 30분 범위로 라운딩 — AI 모델의 동작을 규칙 기반으로 흉내 낸다
- 지도: 실제 지도 타일 또는 정적 SVG 경로 중 구현 단계에서 결정 (고객 화면과 관제 화면이 같은 지도 데이터를 공유)

## 7. 데모 범위 제외 (Out of Scope)

- TMAP/네이버지도 **실제 API 연동** — 교통 이슈는 시뮬레이터 주입으로 재현
- 카카오 알림톡 **실제 발송** — 화면 내 수신 UI로 재현
- **AI 예측 모델 실물** — 규칙 기반 목업으로 대체
- **기사 앱 화면** — 기사 행동은 컨트롤러가 이벤트로 주입
- 기능 ①(권역 설정 최적화), 실 결제, 실 주문 연동
